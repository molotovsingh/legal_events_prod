# Bug Report — MinIO Public Endpoint Replacement Logic Fragile

Date: 2025-11-06
Timestamp: 2025-11-06T03:13:35Z (UTC)
Author: Codex CLI assistant

## Summary

`MinioStorage.generate_upload_url` replaces the presigned URL’s endpoint with a `MINIO_PUBLIC_ENDPOINT`. The current logic may mis-handle cases where the public endpoint already includes a scheme or differs in scheme from the internal endpoint.

## Evidence
- api/storage.py:39–41 — adds `MINIO_PUBLIC_ENDPOINT` (string)
- api/storage.py:64–73 — builds a `scheme` and then constructs `internal_url` and `public_url` using string concatenation and a heuristic `('https' in self.public_endpoint)` to detect scheme.

Potential issues:
- If `MINIO_PUBLIC_ENDPOINT` includes a scheme, concatenating another scheme yields malformed URLs.
- If public/internal schemes differ (http vs https), the heuristic may be wrong.

## Impact
- Browser uploads could fail if the presigned URL is malformed. Debugging is non-obvious.

## Recommended Fixes
- Parse and rebuild URLs using `urllib.parse` (urlparse/urlunparse) to safely replace netloc while preserving scheme and path/query.
- Document expected forms for `MINIO_PUBLIC_ENDPOINT` (with or without scheme) and handle both.

## Validation Steps
1) Test with `MINIO_PUBLIC_ENDPOINT` values: `localhost:9000`, `127.0.0.1:9000`, `https://minio.example.com:9000`.
2) Verify presigned PUTs succeed from the browser for each case.
