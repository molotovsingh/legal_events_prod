## Summary

The legal events production system has multiple critical integration issues that prevent basic functionality. Key blockers include worker database import failures, missing dependencies, SQLAlchemy 2.0 compatibility issues, and database schema mismatches. These issues make the system non-functional in its current state and require immediate attention before any meaningful testing can proceed.

## Critical Issues (System Blockers)

- Worker database import path incorrect
  - File: worker/tasks.py:23
  - Symptom: `ModuleNotFoundError: No module named 'worker.database'` when worker starts
  - Root cause: Worker tries to import from non-existent `worker.database` module; database session is in `api.database`
  - Fix: Change import to `from api.database import SessionLocal`

- Missing critical dependencies in worker image
  - Files: core/document_processor.py:29 (extract_msg), core/langextract_client.py:11 (langextract)
  - Symptom: ImportError when document processing pipeline starts
  - Root cause: Worker Dockerfile doesn't install PyMuPDF, extract_msg, or langextract dependencies
  - Fix: Add missing dependencies to requirements.txt and ensure they're installed in worker container

- SQLAlchemy 2.0 raw SQL compatibility issues
  - Files: api/main.py:103, api/database.py:167
  - Symptom: Health check fails with "Textual SQL expression should be declared as text('...')"
  - Root cause: Raw SQL strings not wrapped with SQLAlchemy's text() function
  - Fix: Import `from sqlalchemy import text` and wrap queries: `db.execute(text("SELECT 1"))`

- Database schema mismatch for runs metadata column
  - Files: migrations/versions/001_initial_schema.py (column `metadata`), api/models.py:170 (column `run_metadata`)
  - Symptom: Run metadata not persisted to database; data loss
  - Root cause: Migration creates `runs.metadata` column but model expects `runs.run_metadata`
  - Fix: Create Alembic migration to rename column or update model mapping

## Major Issues (High Impact)

- SSE endpoint database session lifecycle issue
  - File: api/main.py:548 (stream_run_progress)
  - Symptom: Server-Sent Events may fail after initial response due to closed database session
  - Root cause: Request-scoped session closes during long-running stream
  - Fix: Create new session inside async generator or use scoped session management

- Worker metadata assignment to wrong attribute
  - File: worker/tasks.py:195
  - Symptom: `run.metadata = {...}` uses reserved SQLAlchemy attribute, data not persisted
  - Root cause: Should use `run.run_metadata` to match database column
  - Fix: Change assignment to `run.run_metadata = {...}`

- Queue statistics API compatibility
  - File: api/queue.py:138–161
  - Symptom: Queue registry count methods may return 0 or raise exceptions in certain RQ versions
  - Root cause: RQ API differences between versions for `.count()` vs `.count` property
  - Fix: Verify RQ version and adjust registry access patterns accordingly

## Minor Issues / Cleanups

- Duplicate dependency in requirements.txt
  - File: requirements.txt
  - Symptom: `python-multipart` appears twice in dependency list
  - Impact: None functional, but causes confusion and potential installation issues
  - Fix: Remove duplicate entry

- Unused imports across multiple files
  - Files: api/main.py (JSONResponse, UploadFile), others
  - Symptom: Import statements for unused modules
  - Impact: Mild lint noise, no functional impact
  - Fix: Remove unused imports

- Frontend file hashing placeholder
  - File: frontend/index.html:235
  - Symptom: Uses `btoa(file.name + file.size)` instead of proper SHA-256 hash
  - Impact: Poor deduplication and integrity checking
  - Fix: Implement proper SHA-256 hashing using Web Crypto API

- Development bind mounts in production compose file
  - File: docker-compose.yml: API and worker service volumes
  - Symptom: Development bind mounts in base compose file instead of override
  - Impact: Production containers have workspace dependencies
  - Fix: Move bind mounts to docker-compose.override.yml for development only

## Amendments (by Co-author: Codex CLI assistant)

The following additional guardrail-aligned concerns should be incorporated into the fix plan:

1) Guardrails: Cross-imports between services
   - Worker imports `api.*` modules (models, storage, queue). This violates the “No Cross-Imports” rule in CLAUDE.md.
   - Remedy: Extract shared functionality into a neutral `infra/` (or `common/`) package used by both services; keep API↔Worker communication via Redis/DB and string-based enqueues.

2) Guardrails: Worker mutates API-owned entities
   - Worker updates `runs` and `documents` (status, metadata), but guardrails designate these as API-owned for writes.
   - Remedy: Worker emits progress only; API updates run/document state (via internal endpoints or a progress consumer). This preserves ownership boundaries.

3) Storage key tenancy consistency
   - Upload presigned keys omit `client_id` while artifact keys include it.
   - Remedy: Unify object keys to `clients/{client_id}/cases/{case_id}/runs/{run_id}/...` across all stages; validate keys server-side.

These items align with the architecture in CLAUDE.md and reduce coupling, improve security, and make scaling simpler.
