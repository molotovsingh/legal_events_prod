# Bug Report — Presigned Upload Key Mismatch (API vs UI Manifest)

Date: 2025-11-05
Timestamp: 2025-11-05T12:56:56Z (UTC)
Author: Codex CLI assistant

## Summary

The API generates presigned upload URLs with placeholder filenames, while the frontend manifest uses the real filenames to construct `storage_key`. This mismatch leads the worker to look for objects that were never uploaded under the expected key.

## Evidence
- API — presign uses placeholder name: `api/storage.py`
  - `object_name = f"cases/{case_id}/runs/{run_id}/docs/{filename}"`
- API — run creation returns generic presigned URLs without mapping to actual filenames: `api/main.py`
  - In `/v1/runs` handler, presigned URLs are generated as `document_{i}.pdf` placeholders.
- Frontend — manifest uses actual filename:
  - `storage_key: cases/${caseId}/runs/${runId}/docs/${file.name}` (frontend/index.html)

Impact: After PUT to the presigned URL, the object is stored under `document_{i}.pdf`, but the worker later tries to download `.../docs/${file.name}`, causing a miss.

## Impact
- Run processing fails (documents not found in storage) or results in empty event extraction.
- Confusing user experience: uploads appear to succeed, but processing breaks.

## Recommended Fixes

Option A (preferred): Two-step presign with filenames
- Client sends filenames first → API returns an array of `{filename, storage_key, upload_url}`.
- UI uploads each file to the corresponding `upload_url` and uses the exact `storage_key` in manifest.

Option B: Single-step but include mapping
- Keep `/v1/runs` but accept `file_names` (or `files[]`) so API can return matched `{filename, storage_key, upload_url}`.

Option C: UI computes storage key and requests presign per file
- New endpoint: `/v1/runs/{run_id}/presign?filename=...` returns `{storage_key, upload_url}` per file.

Validation Steps
1) Create run and request presigned URLs with actual filenames.
2) Upload via UI; verify `storage_key` matches exactly what was presigned.
3) Process run; worker successfully downloads documents and extracts events.

Guardrails
- Maintain storage tenancy consistency: include `clients/{client_id}/cases/{case_id}/runs/{run_id}/docs/{filename}` if client_id is available.
