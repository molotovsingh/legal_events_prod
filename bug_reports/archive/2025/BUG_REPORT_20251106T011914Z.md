# Bug Report — XSS Risk via innerHTML Rendering of Event Data

Date: 2025-11-06
Timestamp: 2025-11-06T01:19:14Z (UTC)
Author: Codex CLI assistant

## Summary

The UI inserts event data directly into the DOM using `innerHTML` with template literals. If event fields contain HTML/JS (from document text or LLM output), this can result in cross-site scripting (XSS).

## Evidence
- frontend/index.html:432–439 — builds table rows with template literals, inserting `event.event_particulars`, `event.citation`, `event.document_reference` directly into `innerHTML`.

## Impact
- XSS vulnerability when displaying untrusted content. Legal documents or LLM responses may contain HTML-like strings.

## Recommended Fixes

Option A (preferred): Use textContent
- Create table cells and set `.textContent` for untrusted fields instead of `innerHTML`.

Option B: Escape content
- Sanitize/escape HTML special chars before inserting strings into `innerHTML`.

Additional
- Consider a small sanitize util (e.g., DOMPurify) if the UI grows.

## Validation Steps
1) Simulate an event with `<script>` or `<img onerror>` in a field; verify it renders as text, not executed.
2) Confirm no regression in layout or export functions.
