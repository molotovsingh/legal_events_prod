# Bug Report — Frontend Upload Path Omits client_id (Tenancy)

Date: 2025-11-06
Timestamp: 2025-11-06T01:19:28Z (UTC)
Author: Codex CLI assistant

## Summary

The frontend constructs `storage_key` for uploaded documents without `client_id` (e.g., `cases/{caseId}/runs/{runId}/docs/{file.name}`), while artifact paths include `clients/{client_id}`. This inconsistency complicates tenancy segregation and can lead to collisions.

## Evidence
- frontend/index.html:284 — `storage_key: \`cases/${caseId}/runs/${runId}/docs/${file.name}\``
- worker/tasks.py:386/401/427 — artifact paths include `clients/{client.id}`.

## Impact
- Potential key collisions across tenants if case IDs overlap.
- Harder to enforce per-tenant lifecycle and auditing.

## Recommended Fixes
- Include `clients/{clientId}` in upload `storage_key` to match artifact schema.
- Ensure API presign URLs and worker processing expect the same schema.

## Validation Steps
1) Upload and process with unified path including clientId.
2) List objects by prefix to confirm segregation per tenant.
