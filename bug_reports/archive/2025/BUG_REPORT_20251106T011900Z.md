# Bug Report — Frontend Hardcoded API URL (Ignores Compose API_URL)

Date: 2025-11-06
Timestamp: 2025-11-06T01:19:00Z (UTC)
Author: Codex CLI assistant

## Summary

The frontend uses a hardcoded `API_URL = 'http://localhost:8000'`, which breaks when running inside Docker where the API is reachable at `http://api:8000`. docker-compose sets an `API_URL` env for the frontend container, but the UI doesn’t consume it.

## Evidence
- frontend/index.html:152 — `const API_URL = 'http://localhost:8000';`
- docker-compose.yml:167 — `API_URL: http://api:8000` (unused by the UI)

## Impact
- UI cannot reach the API when served behind Nginx in Docker without port mapping to localhost.
- Confusing configuration; env var suggests configurability that is not present.

## Recommended Fixes

Option A (preferred): Env-injected runtime config
- Serve a small `/config.js` generated at container start that sets `window.APP_CONFIG = { API_URL: ... }`, and read it in index.html.

Option B: Nginx proxy
- Configure Nginx in the frontend container to proxy `/api` → `http://api:8000`, and use relative fetches (`/api/...`) in the UI.

Option C: Build-time inject (less flexible)
- Replace API URL at build time with ARG/ENV; document limitations for multi-env setups.

## Validation Steps
1) Run with docker compose; UI uses configured API URL/proxy.
2) Open UI at http://localhost:3000 and confirm health, create client/case, start run.
