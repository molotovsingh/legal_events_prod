# Bug Report — Idempotency Key Ignored in Run Start

Date: 2025-11-05
Timestamp: 2025-11-05T13:03:48Z (UTC)
Author: Codex CLI assistant

## Summary

`RunManifest` includes an optional `idempotency_key`, but `/v1/runs/{run_id}/start` does not use it. Retrying the same request can insert duplicate `documents` rows or re-trigger processing unintentionally.

## Evidence
- Schema: `api/schemas.py`
  - `class RunManifest(BaseModel): files: List[FileManifestItem]; idempotency_key: Optional[str] = None`
- Endpoint: `api/main.py` `/v1/runs/{run_id}/start`
  - Code creates `Document` rows for each file in `manifest.files` without checking `idempotency_key` or deduping by `sha256`+`filename`.

## Impact
- Duplicate document entries and duplicate processing on retried requests.
- Difficult to ensure at-least-once delivery semantics without manual cleanup.

## Recommended Fixes

1) Respect idempotency per `(run_id, idempotency_key)`
   - Store the last processed key in `Run.run_metadata` and short-circuit if seen.

2) Document-level dedup
   - Upsert documents by `(run_id, sha256, filename)` or reject duplicates with 409/422.

3) Manifest validation
   - Require `idempotency_key` for clients in production mode.

## Validation Steps
1) Start the same run twice with the same `idempotency_key` → second call is a no-op.
2) Start with different key → allowed; verify new docs are inserted.
