# Bug Report — MinIO CORS for Presigned PUT Not Documented

Date: 2025-11-05
Timestamp: 2025-11-05T13:04:11Z (UTC)
Author: Codex CLI assistant

## Summary

Browser uploads to MinIO using presigned PUT URLs can fail due to missing CORS configuration on the MinIO server. The repository does not document the required MinIO CORS policy for presigned uploads, which may lead to opaque failures (preflight, 403) in some environments.

## Evidence
- Frontend performs presigned PUT from the browser (`frontend/index.html` → `axios.put(url, file, { headers: { 'Content-Type': ... }})`).
- MinIO service is started with defaults; CORS policy is not explicitly configured.
- Nginx adds `Access-Control-Allow-Origin *` for the UI, but MinIO must also allow PUT from the browser origin for presigned requests.

## Impact
- Frontend uploads may fail in some environments or browsers, especially with stricter defaults.

## Recommended Fixes

1) Document MinIO CORS configuration
   - Add a snippet to docs/ or README showing `mc admin config set alias api cors` (or `mc cors set`), allowing PUT/GET from `http://localhost:3000` with appropriate headers.

2) Optional: Health check for CORS
   - Add a short script or note to verify a PUT preflight succeeds from the UI origin.

## Validation Steps
1) Configure MinIO CORS to allow `PUT` and `GET` for `http://localhost:3000`.
2) Upload via UI and confirm no preflight errors; verify object appears in bucket.
