# Bug Report — Guardrails Non‑Compliance (Dockerfiles & Compose)

Date: 2025-11-05
Timestamp: 2025-11-05T11:20:00Z (UTC)
Author: Codex CLI assistant

## Summary

The repository violates architectural guardrails documented in `CLAUDE.md` by:
1) Copying cross‑service code into images (API image copies `worker/`, Worker image copies `api/`).
2) Using development bind mounts in the base `docker-compose.yml` (should live in an override file).

This couples services at build/run time and undermines the microservice boundary and immutability requirements.

## References
- Guardrails doc: `CLAUDE.md` → "Guardrails Architecture (v0.2.0+)" and "What Changed in v0.2.0"
- Dockerfiles:
  - `Dockerfile.api` — currently `COPY api /app/api`, `COPY worker /app/worker`, `COPY core /app/core`
  - `Dockerfile.worker` — currently `COPY api /app/api`, `COPY worker /app/worker`, `COPY core /app/core`
- Compose file:
  - `docker-compose.yml` — base file mounts `./api`, `./worker`, `./core` into containers

## Impact
- Breaks service isolation (API can import worker code at runtime and vice‑versa).
- Makes images non‑deterministic (bind mounts override image contents in production).
- Increases risk of accidental cross‑imports and hidden dependencies.

## Recommended Fixes

1) Restrict COPY to service‑specific code
- Edit `Dockerfile.api`:
  - Keep: `COPY api /app/api`
  - Remove: `COPY worker /app/worker`
  - Keep/Review: `COPY core /app/core` (shared library; acceptable if treated as versioned dependency).
- Edit `Dockerfile.worker`:
  - Keep: `COPY worker /app/worker`
  - Remove: `COPY api /app/api`
  - Keep/Review: `COPY core /app/core` (shared library; acceptable if treated as versioned dependency).

2) Move dev bind mounts to override compose
- Remove service `volumes:` bind mounts from base `docker-compose.yml` (production file).
- Create `docker-compose.override.yml` with the dev mounts:
  - API: `./api:/app/api` and `./core:/app/core`
  - Worker: `./worker:/app/worker` and `./core:/app/core`
- Update docs/README to show:
  - Dev: `docker compose up` (auto‑loads override)
  - Prod: `docker compose -f docker-compose.yml up -d`

3) Add CI guard
- Add a simple CI check to prevent cross‑service COPY directives (grep Dockerfiles) and ensure no bind mounts in the base compose.

## Validation Steps
1) Build images after changes:
   - `docker compose -f docker-compose.yml build --no-cache`
2) Run prod mode (no override):
   - `docker compose -f docker-compose.yml up -d`
   - Verify containers do not contain the other service’s code paths.
3) Run dev mode (with override):
   - `docker compose up`
   - Verify hot‑reload and local edits are visible inside containers.

## Notes
- Keeping `core/` in both images is acceptable as a shared library for now; longer‑term, consider packaging it and pinning a version to improve reproducibility.
