## Summary

The system is close to end‑to‑end, but several critical and major issues block reliable document processing. Key blockers are missing worker dependencies, an import path error in the worker, SQLAlchemy 2.0 raw-SQL usage, and a migration/schema mismatch for the `runs` metadata column.

## Critical Issues (Blockers)

- Worker import path wrong for DB session
  - File: worker/tasks.py:23
  - Symptom: `ModuleNotFoundError: No module named 'worker.database'` when worker starts or when a job runs.
  - Root cause: There is no `worker/database.py`; the session lives in `api/database.py`.
  - Fix: Change to `from api.database import SessionLocal`.

- Worker optional deps missing (fitz/PyMuPDF, extract_msg, langextract)
  - Files: core/docling_adapter.py:11 (fitz), core/document_processor.py:29 (extract_msg), core/langextract_client.py:11 (langextract)
  - Symptom: ImportError when pipeline starts; document processing fails.
  - Fix: Ensure Python deps installed (PyMuPDF, extract_msg, langextract via git). Added to requirements and Dockerfiles in this patch set. Rebuild images without cache.

- SQLAlchemy 2.0 raw SQL used with plain strings
  - Files: api/main.py:103, api/database.py:167
  - Symptom: Health check and DB test raise: “Textual SQL expression should be declared as text('...')”.
  - Fix: Use `from sqlalchemy import text` and `db.execute(text('SELECT 1'))`.

- Migration vs model mismatch for runs metadata column
  - Files: migrations/versions/001_initial_schema.py (column `metadata`), api/models.py:170 (column `run_metadata`)
  - Symptom: Data written to `run.run_metadata` won’t persist (column doesn’t exist); previous code wrote to `run.metadata` (reserved attribute) and also didn’t persist properly.
  - Fix: Create Alembic migration to rename column `runs.metadata` → `runs.run_metadata` (and update any references); or change model to map `metadata` with `key='run_metadata'` hybrid name if migration is postponed.

## Major Issues

- SSE endpoint may use a closed DB session during streaming
  - File: api/main.py:548 (stream_run_progress)
  - Symptom: After initial response, periodic queries can fail due to the request-scoped session closing.
  - Fix: Open a new session inside the async generator or manage a scoped session for the stream lifecycle.

- Worker sets `run.metadata` instead of `run.run_metadata`
  - File: worker/tasks.py:195
  - Symptom: Assignment uses reserved attribute; data not persisted to DB.
  - Fix: Change to `run.run_metadata = {...}` and ensure migration fix above is applied.

- Queue stats fields may be off by API drift
  - File: api/queue.py:138–161
  - Symptom: Some registries expose `.count()` (callable) vs property; can report 0 or raise in certain rq versions.
  - Fix: Verify RQ 1.15 API; adjust: `queue.started_job_registry.count` vs `queue.started_job_registry.count` callable if needed.

## Minor Issues / Cleanups

- Duplicate dependency
  - File: requirements.txt
  - Symptom: `python-multipart` listed twice.
  - Fix: Remove duplicate (harmless).

- Unused imports
  - Files: api/main.py (JSONResponse, UploadFile), others
  - Impact: None; mild lint noise.

- Frontend hashing placeholder
  - File: frontend/index.html:235
  - Symptom: Uses `btoa(file.name + file.size)` instead of real SHA‑256.
  - Fix: Use SubtleCrypto to compute SHA‑256 for idempotency/dedup.

- Compose dev mounts in base file
  - File: docker-compose.yml: api/worker volumes
  - Symptom: In production these mounts tightly couple services to the workspace.
  - Fix: Move bind mounts to `docker-compose.override.yml` for dev, keep base immutable.
