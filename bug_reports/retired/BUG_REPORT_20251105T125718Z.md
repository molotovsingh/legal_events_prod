# Bug Report — Duplicate/Conflicting LangExtract Installation Sources

Date: 2025-11-05
Timestamp: 2025-11-05T12:57:18Z (UTC)
Author: Codex CLI assistant

## Summary

The project lists `langextract>=0.1.0` in `requirements.txt` and also installs `langextract` from a Git URL in Dockerfiles. This can cause build instability or conflicts depending on availability/version differences between PyPI and the Git repository.

## Evidence
- requirements.txt: `langextract>=0.1.0` (PyPI source)
- Dockerfile.api and Dockerfile.worker: `pip install langextract@git+https://github.com/google/langextract.git || echo ...`

## Impact
- If PyPI does not host `langextract` or the version differs, `pip install -r requirements.txt` may fail.
- Installing twice (PyPI then Git) increases build time and can mask version mismatches.
- The `|| echo` may allow partially missing optional dependencies, leading to runtime ImportError when the provider is selected.

## Recommended Fixes

Pick one installation source and make it explicit:
- If using PyPI: keep `langextract>=...` in requirements.txt and remove the Git install in Dockerfiles.
- If using GitHub source: remove `langextract` from requirements.txt and pin a specific commit/tag in Dockerfiles: `langextract@git+https://...@<tag-or-sha>`.

Optional:
- Wrap LangExtract provider usage with a capability check and clear error if unavailable.

Validation Steps
1) Build images with `--no-cache` and confirm the chosen source installs cleanly.
2) Run a LangExtract-based extraction to verify runtime import and behavior.
