# Bug Report — Storage Key Tenancy Inconsistency (Upload vs Artifacts)

Date: 2025-11-05
Timestamp: 2025-11-05T11:39:02Z (UTC)
Author: Codex CLI assistant

## Summary

Storage object keys for uploads and artifacts are inconsistent in tenancy scoping. Upload URLs omit `client_id` while artifacts include it. This inconsistency increases risk of collisions or tenant leakage.

## Evidence
- Upload presign path (no client): `api/storage.py`
  - `object_name = f"cases/{case_id}/runs/{run_id}/docs/{filename}"` (line ~76)
- Artifact paths (include client): `worker/tasks.py`
  - `clients/{client.id}/cases/{case.id}/runs/{run_id}/artifacts/{run_id}.csv|xlsx|json` (lines ~386, ~401, ~427)

## Impact
- Keys for different tenants could collide if `case_id` overlaps across clients.
- Harder to enforce per‑tenant lifecycle/retention and auditing.

## Recommended Fixes

1) Unify object key schema across all stages
   - Include `client_id` consistently: `clients/{client_id}/cases/{case_id}/runs/{run_id}/...` for docs and artifacts.
   - Alternatively, include a globally unique tenant prefix in all keys.

2) Update manifest and UI
   - Ensure the UI `storage_key` mirrors the unified schema.
   - Regenerate presigned URLs accordingly.

3) Add validation
   - Validate `storage_key` matches expected prefix for the specified client/case before processing.

## Validation Steps
1) Create a run and upload documents; verify presigned upload keys include `clients/{client_id}`.
2) Process run; confirm artifact keys match the same prefix.
3) List objects by prefix to confirm segregation per client.
