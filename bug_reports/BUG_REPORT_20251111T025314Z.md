# Bug Report — Critical Resource Leaks and State Corruption Issues

**Date:** 2025-11-11  
**Timestamp:** 2025-11-11T02:53:14Z (UTC)

## Summary

Code audit identified **9 critical and high-severity bugs** spanning resource management, null safety, and graceful shutdown. Three bugs (Redis connection leaks and None type error) pose production risk: unchecked connection leaks can exhaust Redis connection pools under load, and a missing null check in export processing can crash with AttributeError. Event consumer infinite loop prevents graceful shutdown. All bugs have clear reproduction paths and targeted fixes.

---

## Critical Issues

- **api/main.py:155–162** — Redis health check connection leak. Calling `/health` endpoint repeatedly when Redis is unavailable leaks connections (no `r.close()` in except block). Fix: Wrap in `finally` block to ensure `r.close()` always executes.

- **api/main.py:904–913** — Redis idempotency cache connection leak in `retry_run` endpoint. Early return on cache hit (line 910) bypasses `r.close()`, and exception handler (line 912–913) also missing cleanup. Fix: Use `finally` block; move `r.close()` outside conditional.

- **worker/tasks.py:397–399** — Missing null check before attribute access. Code assumes `case` and `client` exist after database queries (`.first()` returns `None` if not found), leading to `AttributeError: 'NoneType' object has no attribute 'client_id'` on line 399. Fix: Add explicit `if not case` / `if not client` guards with error logging.

---

## Major Issues

- **worker/tasks.py:76–77** — MinioStorage instance created but never cleaned up in `process_run()`. Long-running worker accumulates unclosed storage connections, eventually exhausting MinIO connection pool. Fix: Add `storage.close()` in `finally` block (requires implementing `close()` method in MinioStorage if missing).

- **infra/worker_events.py:213–219** — Event consumer infinite loop with no shutdown signal. `self.pubsub.listen()` blocks forever; calling `stop()` (lines 221–225) cannot interrupt the blocking loop. Worker thread may not exit cleanly on shutdown. Fix: Add `self.running` flag check inside loop; call `stop()` to set flag and break loop.

- **infra/worker_events.py:216–219** — Silent error swallowing in event processing callback. Failed event parsing logged but not queued to Dead Letter Queue (DLQ infrastructure exists in `api/event_processor.py:31` but not used here). Events lost permanently, causing API/worker state divergence. Fix: Integrate with DLQ; move failed events to Redis DLQ for manual inspection.

- **api/event_processor.py:228–234** — Potential race condition in document status updates. No locking on concurrent reads/writes to `doc.status`. Two simultaneous retry events could both read status, both write, causing lost updates. Fix: Add row-level lock or use optimistic locking with version column.

---

## Minor Issues / Cleanups

- **worker/tasks.py:507–516** — Cleanup function aborts on first storage error. `storage.list_objects(prefix)` can fail (network issue, MinIO unavailable), causing entire cleanup job to fail and skip remaining runs. Fix: Wrap storage operations in try/except with per-run error handling and continue loop.

- **api/main.py** + **infra/worker_events.py** — Blocking event consumer in application shutdown path. `pubsub.listen()` blocks thread indefinitely; `thread.join(timeout=5)` (event_processor.py:77) may timeout during graceful shutdown. Fix: Implement signal-based or flag-based loop break; reduce blocking time.

## Repro Steps

### Bug #1–2: Redis Connection Leaks

1. Start system with Redis running
2. Call `curl http://localhost:8000/health` repeatedly (10+ times quickly)
3. Stop Redis server
4. Call `curl http://localhost:8000/health` 5–10 more times
5. Check Redis connection count: `redis-cli INFO | grep connected_clients`
6. Expected: ~1 connection; Actual: 5+ leaked connections

### Bug #3: None Type Error in Export

1. Create client, case, run normally
2. Manually delete the case from database: `DELETE FROM cases WHERE id = <case_id>`
3. Call export endpoint: `POST /v1/runs/<run_id>/export`
4. Expected: 404 with "Case not found" error; Actual: 500 with `AttributeError`

### Bug #5: Event Consumer Shutdown

1. Start application
2. Observe event processor thread started: `ps aux | grep worker_events`
3. Kill application with SIGTERM
4. Observe: Thread takes >5 seconds to exit (timeout in join)
5. Check logs for "Event processor stopped" message (may not appear)
