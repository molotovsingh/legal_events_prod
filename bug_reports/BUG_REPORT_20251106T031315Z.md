# Bug Report — Worker DB Module: SQLAlchemy 2.0 Compatibility & Base Import

Date: 2025-11-06
Timestamp: 2025-11-06T03:13:15Z (UTC)
Author: Codex CLI assistant

## Summary

The new `worker/database.py` improves service separation, but has two SQLAlchemy 2.0 concerns: (1) uses deprecated `declarative_base` import path, and (2) executes raw SQL without wrapping in `text()`.

## Evidence
- worker/database.py:15 — `from sqlalchemy.ext.declarative import declarative_base` (deprecated path in SA 2.0; use `sqlalchemy.orm.declarative_base`).
- worker/database.py:48 — `db.execute("SELECT 1")` (should be `db.execute(text("SELECT 1"))` with `from sqlalchemy import text`).

## Impact
- Potential deprecation warnings or errors depending on SQLAlchemy version; inconsistent with API module which already uses `text()`.

## Recommended Fixes
- Replace import with `from sqlalchemy.orm import declarative_base`.
- Use `from sqlalchemy import text` and wrap raw SQL in `text("SELECT 1")`.
- Optional: align logging/test_connection semantics with API.

## Validation Steps
1) Import the module under SA 2.0 and run `test_connection()`; no warnings/errors.
