## [0.12.0] - 2025-11-28 (UNRELEASED)

### Added
- Token counting and cost estimation infrastructure
  - Pre-run cost estimation via POST /v1/estimate-tokens endpoint
  - Post-run token usage tracking via GET /v1/runs/{run_id}/token-usage endpoint
  - Provider-specific tokenizer support (GPT via tiktoken, Llama via transformers, Claude via anthropic)
  - Accurate input token counting before document processing
  - Per-document token breakdown and total cost calculation
- Classification Layer 1.5 (optional document classification)
  - GET /v1/classifiers endpoint to list available classification models
  - Optional pre-processing document classification (categorize before extraction)
  - Classification results persisted as artifacts
  - GET /v1/runs/{run_id}/classification endpoint to retrieve results
  - Classification token usage tracking (separate from event extraction)
- Token counter core module (core/token_counter.py)
  - Provider-agnostic tokenizer resolution
  - Supports OpenAI GPT models via tiktoken
  - Supports Llama models via HuggingFace transformers
  - Supports Claude models via anthropic tokenizer
  - Explicit error handling (TokenizerUnavailable exception)
  - No silent fallbacks (fails loud when tokenizer unavailable)
- Frontend cost estimation features
  - "Estimate Cost" button in upload interface
  - Live cost preview showing input tokens and estimated cost
  - Classification toggle and model selector
  - Token usage display in run details modal
  - Per-document token breakdown visualization

### Changed
- OpenRouter adapter enhanced with usage token extraction
  - Extracts prompt_tokens, completion_tokens, total_tokens from API responses
  - Attaches usage metadata to EventRecord attributes
  - Enables accurate post-run cost tracking
- OpenRouter classifier enhanced with usage token extraction
  - Classification responses now include token usage
  - Separate tracking for classification vs extraction tokens
- Worker task pipeline extended for token tracking
  - Accumulates token usage per document
  - Generates token_usage.json artifact
  - Fallback counting when adapter doesn't provide usage
  - Classification Layer 1.5 integration (optional pre-processing)
- Frontend UI simplified and polished
  - Compact header design
  - Tighter spacing for production-ready layout
  - Streamlined login modal
- Run metadata schema extended (backward compatible)
  - Added optional enable_classification field (default: false)
  - Added optional classification_model field

### Dependencies
- Added tiktoken>=0.7.0 for OpenAI GPT tokenization (~1MB)
- Added transformers>=4.45.0 for Llama tokenization (~500MB + PyTorch dependency)
- Added sentencepiece>=0.1.99 for Llama tokenizer backend (~2MB)
- **Note:** transformers may be made optional in deployment configuration

### Technical Details
- No database migrations required (all data stored as artifacts)
- All new endpoints are backward compatible
- No breaking changes to existing API contracts
- Token usage stored in MinIO as JSON artifacts
- Classification results stored in MinIO as JSON artifacts
