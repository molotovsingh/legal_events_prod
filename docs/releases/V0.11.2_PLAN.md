## Scope

This release focuses on resolving 3 critical P1 bugs related to resource management and graceful shutdown:

### Issue #1: MinioStorage Resource Leak
**Priority:** P1 (Major)
**Effort:** 30 minutes
**File:** `infra/storage.py`

**Problem:**
- MinioStorage creates HTTP connection pools that are never closed
- Long-running workers accumulate stale connections
- Eventually causes connection pool exhaustion

**Solution:**
```python
class MinioStorage:
    def close(self):
        """Close HTTP connection pool"""
        try:
            if hasattr(self, '_client') and hasattr(self._client, '_http'):
                self._client._http.clear()
        except Exception as e:
            logger.warning(f"Error closing MinioStorage: {e}")
```

**Usage in worker:**
```python
storage = MinioStorage()
try:
    # ... process documents ...
finally:
    storage.close()
```

### Issue #2: Event Consumer Infinite Loop Blocks Shutdown
**Priority:** P1 (Major)
**Effort:** 20 minutes
**File:** `api/event_processor.py`

**Problem:**
- Event consumer runs in infinite `while True` loop
- No mechanism to break loop on shutdown signal
- Worker containers can't shut down gracefully within timeout window

**Solution:**
```python
class APIEventProcessor:
    def __init__(self):
        self.running = False  # Add running flag
        # ... existing init ...

    def start(self):
        self.running = True
        # ... existing start logic ...

    def stop(self):
        logger.info("Stopping event consumer...")
        self.running = False  # Signal to stop
        # ... existing cleanup ...

    def _consume_events(self):
        while self.running:  # Changed from while True
            try:
                # ... existing event consumption ...
            except Exception as e:
                if not self.running:
                    break  # Exit cleanly on shutdown
                # ... handle error ...
```

### Issue #3: Silent Error Swallowing in Event Consumer
**Priority:** P1 (Major)
**Effort:** 25 minutes
**Files:** `api/event_processor.py`, `infra/worker_events.py`

**Problem:**
- Failed events are logged but not persisted
- No way to replay or investigate failed event processing
- Data loss risk if events fail repeatedly

**Solution:**
Integrate with existing Dead Letter Queue (DLQ) pattern:

```python
def _consume_events(self):
    while self.running:
        try:
            # ... existing event consumption ...
        except Exception as e:
            logger.error(f"Event processing failed: {e}", exc_info=True)

            # Push to DLQ for manual inspection
            try:
                event_data = {
                    'event_type': event.type,
                    'event_data': event.data,
                    'error': str(e),
                    'timestamp': datetime.utcnow().isoformat()
                }
                self.redis_client.rpush(
                    "worker:events:dlq",
                    json.dumps(event_data)
                )
                self.redis_client.expire("worker:events:dlq", 604800)  # 7 days
            except Exception as dlq_error:
                logger.error(f"Failed to push to DLQ: {dlq_error}")
```

**Monitoring:**
```bash
# Check DLQ depth
redis-cli LLEN "worker:events:dlq"

# Inspect failed events
redis-cli LRANGE "worker:events:dlq" 0 -1
```
