## v0.12.0 Feature: Token Counting & Cost Estimation

### Feature Scope
**Primary Goal:** Accurate pre-run and post-run token counting with cost estimation

### Architecture Components

#### 1. Token Counting Core (`core/token_counter.py`) ✅ COMPLETE
**Status:** Implemented, not tested
**Capabilities:**
- Provider-agnostic tokenizer resolution
- Supports GPT family (tiktoken), Llama (transformers), Claude (anthropic-tokenizer)
- Plain text and chat messages support
- Raises `TokenizerUnavailable` for unsupported models (no silent fallbacks)

**Implementation Quality:** HIGH
- Clean separation of concerns
- Explicit error handling
- Optional dependencies with clear error messages

#### 2. Pre-Run Estimation Endpoint ✅ PARTIALLY COMPLETE
**Endpoint:** `POST /v1/estimate-tokens`
**Status:** Backend implemented, frontend integrated

**Request Flow:**
1. Frontend uploads files to `/v1/upload` (temp storage)
2. API runs Docling extraction on uploaded files
3. Token counter calculates exact input tokens for selected provider/model
4. Optional: Classification input tokens (if enabled)
5. Returns per-document breakdown + total cost estimate

**Implementation Status:**
- ✅ API endpoint defined
- ✅ Schema defined (`TokenEstimateRequest`, `TokenEstimateResponse`)
- ✅ Frontend JS function `estimateCost()` implemented
- ✅ UI preview element added
- ⚠️ **INCOMPLETE:** API endpoint body partially shown in diff (truncated at line 87)
- ❌ **NOT TESTED:** No validation of accuracy or error handling

**Known Gaps:**
- API implementation may be incomplete (diff truncated)
- No error handling for tokenizer failures visible
- No test coverage
- Pricing lookup from `model_catalog` not verified
- Classification model pricing integration unclear

#### 3. Post-Run Token Tracking ✅ COMPLETE
**Endpoint:** `GET /v1/runs/{run_id}/token-usage`
**Status:** Fully implemented

**Data Flow:**
1. Worker extracts usage tokens from adapter responses (OpenRouter, Anthropic)
2. Fallback: Count input tokens from extracted text when no usage provided
3. Accumulates event + classification tokens per document
4. Uploads `token_usage_json` artifact to MinIO
5. API serves artifact via `/v1/runs/{run_id}/token-usage`
6. Frontend displays in run details modal

**Implementation Quality:** HIGH
- Dual-mode tracking (adapter-provided + fallback)
- Per-document granularity
- Persisted as artifact (audit trail)
- Frontend integration complete

#### 4. Classification Layer (Layer 1.5) ✅ COMPLETE

## Dependency Analysis

### New Dependencies Added to `requirements.txt`

```python
# Tokenizers for accurate token counting (pre-run + post-run)
tiktoken>=0.7.0          # OpenAI GPT family tokenizer
transformers>=4.45.0     # HuggingFace tokenizers (Llama, etc.)
sentencepiece>=0.1.99    # Llama tokenizer dependency
```

### Impact Assessment

| Dependency | Size | Purpose | Required For | Optional? |
|-----------|------|---------|-------------|-----------|
| tiktoken | ~1MB | GPT tokenization | OpenAI, OpenRouter GPT models | No - common |
| transformers | ~500MB | Llama tokenization | OpenRouter Llama models | Yes - conditional |
| sentencepiece | ~2MB | Llama tokenizer backend | transformers Llama support | Yes - conditional |
| torch | ~800MB | transformers dependency | transformers | Yes - conditional |

**Total Size Impact:** ~1.3GB (if all included)

### Optimization Recommendations

#### Option 1: Make Transformers Optional (Recommended)
```python
# requirements.txt - core
tiktoken>=0.7.0

# requirements-transformers.txt - optional
transformers>=4.45.0
torch>=1.12.0
sentencepiece>=0.1.99
```

**Approach:**
- Install transformers only if Llama models are enabled
- Fallback to character-based estimation if tokenizer unavailable
- Document deployment options (with/without transformers)

#### Option 2: Pre-download Tokenizer Files
```dockerfile
# In Dockerfile
RUN python -c "from transformers import AutoTokenizer; \
    AutoTokenizer.from_pretrained('meta-llama/Meta-Llama-3.1-8B')"
```

**Benefits:**
- No network dependency on worker startup
- Faster first-run experience

**Drawbacks:**
- Increases image size by ~500MB (tokenizer files)

#### Option 3: Lazy Initialization (Current Implementation)
```python
# token_counter.py already implements this
def _get_llama_tokenizer(model_id: str) -> Callable[[str], int]:
    try:
        from transformers import AutoTokenizer
    except Exception as e:
        raise TokenizerUnavailable(
            "transformers is required for Llama models..."
        ) from e
```

**Status:** Already implemented ✅
**Recommendation:** Add runtime check on startup to warn if enabled models lack tokenizers
