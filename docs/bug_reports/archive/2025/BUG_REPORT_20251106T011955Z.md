# Bug Report — Weak File Hashing Placeholder (Use Real SHA‑256)

Date: 2025-11-06
Timestamp: 2025-11-06T01:19:55Z (UTC)
Author: Codex CLI assistant

## Summary

The UI uses a placeholder hash `btoa(file.name + file.size)` instead of computing a real SHA‑256 of file contents. This is insufficient for idempotency/deduplication and integrity signaling.

## Evidence
- frontend/index.html:277–285 — `const sha256 = btoa(file.name + file.size).substring(0, 64);`

## Impact
- Duplicate detection and idempotency checks are ineffective; collisions likely.

## Recommended Fixes
- Use Web Crypto API: `crypto.subtle.digest('SHA-256', fileArrayBuffer)` and encode to hex.
- Compute asynchronously and show a small progress indicator if needed.

## Validation Steps
1) Upload two identical files with different names → same digest.
2) Upload different files with same size → different digest.
