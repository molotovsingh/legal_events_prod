# Bug Report — SSE & Dependency Alignment (FastAPI/Starlette/sse-starlette)

Date: 2025-11-06
Timestamp: 2025-11-06T03:35:45Z (UTC)
Author: Codex CLI assistant

## Summary

SSE reliability depends on compatible versions of FastAPI, Starlette, and `sse-starlette`. Current requirements pin only FastAPI (>=0.115.0) and `sse-starlette>=1.6.5`, which may not include fixes in `sse-starlette` 3.x and in FastAPI 0.118 for `StreamingResponse` cleanup. Align versions and rules to avoid subtle streaming issues.

## Evidence
- requirements.txt: `fastapi>=0.115.0`, `sse-starlette>=1.6.5`.
- SSE endpoint: `api/main.py:/v1/runs/{run_id}/stream` uses `EventSourceResponse` from `sse_starlette`.

Known considerations:
- FastAPI 0.115.x required Starlette ~0.40–0.42 initially; later patches extended ranges. Don’t pin Starlette directly; let FastAPI resolve.
- `sse-starlette` 3.0.0+ fixes multi-loop/thread issues and lifespan warnings; latest 3.0.2 is recommended.
- FastAPI 0.118.x fixes `StreamingResponse` cleanup timing; helpful for generator-based SSE or resource cleanup.
- Avoid GZipMiddleware for SSE.

## Impact
- Potential SSE hangs, premature cleanup, or incompatibilities under certain deployment setups or test harnesses.

## Recommended Fixes
1) Upgrade path (test in a branch):
   - FastAPI → 0.118.x
   - `sse-starlette` → 3.0.2
   - Do not pin Starlette; let FastAPI manage compatible version.
2) Endpoint hygiene:
   - Ensure generator closes DB session (see separate SSE lifecycle bug).
   - Avoid compression on SSE route.
   - Optionally detect client disconnects to stop work.

## Validation Steps
1) Rebuild images with updated deps; run `./start.sh start` and hit `/v1/runs/{id}/stream` while processing.
2) Confirm continuous delivery of events; no buffering or early cleanup.
