# Bug Report — Auth Disabled and Default Secrets in Production Config

Date: 2025-11-05
Timestamp: 2025-11-05T11:39:18Z (UTC)
Author: Codex CLI assistant

## Summary

Authentication is disabled in the API and default credentials are present for MinIO and sample secrets. For production, this violates basic security posture.

## Evidence
- `api/main.py`: Commented auth with explicit warning — "SECURITY WARNING: Authentication is currently disabled!"
- `docker-compose.yml`: MinIO credentials hardcoded (`MINIO_ROOT_PASSWORD: minioadmin123`, `MINIO_SECRET_KEY: minioadmin123`).
- `start.sh`: Example secrets (`JWT_SECRET_KEY`, `API_KEY_ADMIN`) with placeholder values.

## Impact
- Unauthenticated API in production would expose data.
- Default storage credentials are widely known; risk of data exfiltration.

## Recommended Fixes

1) Enable auth behind a flag
   - Introduce `ENABLE_AUTH=true` env for production; wire JWT validation middleware and protected routes.

2) Secrets management
   - Replace hardcoded MinIO creds with environment overrides sourced from `.env` or Docker secrets.
   - Use Docker secrets or a secrets manager (Vault, SSM) for JWT keys and API keys.

3) Deployment guidance
   - Add DEPLOYMENT.md with a checklist: rotate defaults, provide sample secure config, and verify with a `/health/security` check.

## Validation Steps
1) Start stack with `ENABLE_AUTH=true`; confirm `/v1/*` endpoints require JWT.
2) Confirm MinIO creds come from secrets and not defaults.
3) Run a smoke test accessing artifacts to ensure no anonymous access.
